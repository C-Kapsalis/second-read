# Documentation and Diátaxis

Use Second Read's existing docs skill to classify tutorial, how-to, reference or explanation by user need, not label. Verify prerequisites before usage, example-to-spec consistency, executable command results when authorized, complete links when checkable, and observable success. Separate product-source corroboration from an actually executed workflow. A README should help users find a successful starting path without becoming a copy of the entire docs site. An unfamiliar reader should know which page to visit and what they must supply next.

Sequence question: “At this exact step, have we already told the reader how to obtain the required file, key or environment variable?” If not, propose moving the prerequisite or inserting a precise, factual step; never invent a command or default.
